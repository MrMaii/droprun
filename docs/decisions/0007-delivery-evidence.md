# ADR 0007：先核对交付证据，再发布完成

状态：Accepted（证据门禁保留；副本基线部分 Superseded）  
日期：2026-09-07

2026-09-07：与副本路径、原快照基线有关的部分由 [ADR 0009](./0009-original-project-plan-approval.md) 取代；新原目录任务仍核对显式产物哈希和真实命令，计划报告不能作为完成交付。下文历史门禁与证据不重写。

## 背景

原报告 v1 虽然区分模型自述与命令事件，但“构建通过”与真实命令退出码1可以同时出现，仍发布 completed。协议回合结束、JSON 合法与业务完成不是同一事实。

## 决定

- 新报告 v2 声明文件产物及 SHA-256，验证项引用执行器实际命令 id。
- Connector 保留当前回合全部精简事件，并提供本机只读凭据清单供 agent 引用。手机继续显示最近25条，云端无需新字段。
- 结构正确的成功报告先保持 running；产物与命令核对后才能成为 completed，失败则 blocked。取消/失败仍优先，不从未知证据推导成功。
- 校验普通文件、相对路径、链接、实际字节哈希；删除必须对应原快照文件且已不存在。
- 引用的验证必须存在、退出码0且状态completed；同命令同cwd后续失败、引用早于最后一次已完成文件修改事件，均需要重新验证。
- 允许 analysis 与 not_applicable，不要求为了交付强行写文件；但至少有一次真实材料/项目核对，且不能与本轮源码净变更矛盾。
- 追问比较本轮开始和结束指纹，不把前轮产物当作本轮新改动。保留已发布历史报告；恢复旧未发布报告时不伪造新版证据。

## 明确限制

这是机械证据门禁，不是通用业务裁判。命令退出0不证明测试有断言或覆盖充分；引用一条成功命令不自动证明验证描述准确。文件哈希不证明符合用户意图，Agent 仍可能漏报产物或误判任务属于仅分析。

显式 fileChange 事件的先后关系可检查；经普通 shell 命令写文件的精确时点、未被 Git 列出的忽略文件、外部系统副作用没有被全面证明。产物核对后继续由其他客户端修改也不由本门禁锁定。不能据此宣称完整业务验收或完成整个 MVP。

未引用的失败命令仍保留并展示；搜索无匹配等非零退出不能一律让所有任务失败。新 schema 只用于新任务和未发布恢复，历史终态不重写。

## 替代方案

- 只要求模型声明“完成”：已证实不足。
- 只检查任意文件存在：不能证明目标文件、内容或验证。
- 任何命令非零都永久失败：会把正常搜索无结果和已修复重试当成失败。
- 自动重跑报告中的命令：可能重复修改或产生外部副作用，因此只核对实际执行记录，不执行模型给出的新命令。

## 验证

`tests/delivery.test.mjs`、`tests/report.test.mjs` 覆盖机械门禁；真实任务链路由 `scripts/delivery-e2e.mjs` 一次性创建正例与明确标注的合成反例。实际运行时间、结果、Android缓存/界面证据单独记入 MVP验收账本（历史私人验收记录，未随公开版分发），不以脚本存在代替通过。
