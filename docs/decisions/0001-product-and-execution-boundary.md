# ADR 0001：产品与自动执行边界

状态：Superseded（默认自动执行与隔离副本部分；其他产品边界保留）  
日期：2026-09-07

2026-09-07 后续用户决定见 [ADR 0009](./0009-original-project-plan-approval.md)：新任务使用原目录，默认先只读计划并由手机批准，直接执行由手机主动开启。下文保留原决定背景，不再作为新任务默认模式。

## 背景

最初想法是让用户把手机刷到的视频像发进员工群一样交给 Claude 或 Codex。讨论中出现两个可能方向：只分析并给建议，或在授权范围内直接工作、最后报告。

用户后续明确要求：一次分享进入选定项目的新会话；材料和留言一起交给 agent；无留言时 agent 自主判断；结束后报告“看到了什么、应该用在哪里、做了什么”。

## 决定

- DropRun 定位为项目任务中转与交付层，不是视频摘要或收藏工具。
- 项目首次连接时配置长期权限。
- 在该权限范围内，agent 可以自动完成可恢复、可核验的工作，不要求每次先给建议。
- 生产发布、生产数据、付费、对外发送、重要删除等高风险动作必须逐次授权。
- 材料不适用时可以不修改，并作为有效结果交付。

## 理由

仅返回建议会把“再次打开电脑、再次交办”的工作留给用户，削弱核心价值。完全无边界自动执行则把用户的灵感分享错误地解释为无限授权。项目级预授权加高风险逐次审批平衡了两者。

## 后果

- 权限边界必须由 Connector 和 sandbox 落实，不只写进提示词。
- 写任务需要隔离工作副本、冲突检查和可核验报告。
- 手机端需要显示审批状态。
- PRD 不以“默认只分析”作为产品基线。

## 验证

- 安全范围内的任务可以无人值守完成。
- 超范围操作会暂停并在手机请求审批。
- 恶意材料不能扩大权限。
- 不适用材料不会制造无意义改动。
