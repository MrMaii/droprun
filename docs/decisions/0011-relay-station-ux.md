# ADR 0011：定位为转发中转站，Codex 作为前台

日期：2026-09-09  
状态：已采纳，随 0.2.0 上线

## 背景

0.1.7 之前的手机端把配对、计划审批、项目授权、执行模式、交付预览堆在同一个首页；配对需要手动输入 20 位配对码；发往 Codex 的第一条消息是一整段协议要求（JSON Schema、凭据文件、命令 ID），材料只给了文件清单，实际内容要靠 Codex 自己再去读；默认「先计划后批准」意味着每次转发都要再回到手机点一次。用户反馈这些叠加起来让产品「没有办法正常使用」。

## 决定

1. **产品定位是中转站。** 手机端只有一个仪表盘（正在进行 / 累计转发 / 进行中列表 / 最近）和一个设置入口。分享入口来自系统分享菜单，不在首页放任务创建按钮。
2. **配对用二维码。** Connector 在 `http://127.0.0.1:47493/pair` 生成一次性配对码并渲染二维码；手机内置扫码（Camera2 + ZXing core，纯 Java 依赖），系统相机扫到 `https://<relay>/pair#code=…` 也能通过 App Link / `droprun://pair` 打开应用。手动输入保留为兜底。配对码本身仍只经 URL 片段传递，不进入服务器日志。
3. **分享流程固定为：选项目 → 留言 → 模型与推理强度 → 提交。** 模型目录由 Connector 从 Codex `model/list` 同步到 Relay，Relay 校验模型与强度组合后写入任务；Connector 在 `turn/start` 传 `model` 与 `effort`。
4. **新配对的手机默认直接执行。** 提交后用户可以直接去电脑上的 Codex 看进展。「先看计划」变成设置中的可选项（原 ADR 0009 的审批流程保留，不再是默认）。已有设备的设置不自动改动。
5. **Codex 是前台，不是后端。** 可见的第一条消息只包含用户留言和已提取的材料摘要（标题、作者、时长、简介、文字稿/字幕、关键帧、读取范围）；工作规则和报告格式放进 `developerInstructions`。最终消息是给人读的 Markdown，只在末尾附一个 ```droprun 证据块；计划回合直接输出 Markdown。
6. **证据 v3。** 证据块只声明 `outcome`、`artifacts`（相对路径）、`verification`（真实运行过的命令原文）、`remaining`。执行器自己核对：产物存在且本回合产生（文件事件或修改时间），验证命令与成功的执行记录匹配且晚于最后一次编辑，有文件变更就必须声明产物。缺少证据块时用带 JSON Schema 的一次补问获取，不重跑工作。这替代 ADR 0007 中要求模型自报 SHA-256 与命令 ID 的做法；反幻觉目标不变。
7. **材料提取尽量在 Connector 完成。** yt-dlp 失败时回退到网页 Open Graph 元数据并下载封面；可配置 `cookiesFromBrowser` 让提取器使用已登录浏览器会话；附件视频用 ffprobe 取时长；转写与字幕文本直接写进给 Codex 的消息。

## 影响

- Relay 新增 `tasks.model/effort/title/material_summary` 列（migration 0007）、`/pair` 页面、`/.well-known/assetlinks.json`、`GET /tasks` 的 `stats`、`/connector/sync` 的 `models`。
- 旧 App（0.1.7）仍能提交任务（不带模型字段），仍按各自设备设置执行。
- 计划审批、单次命令审批、项目授权、交付文件、追问功能保留，只是从首页移到任务详情和设置。
- 「已完成」仍需证据核对通过；核对失败显示为「需要处理」并给出原因，改动仍在原项目里。
