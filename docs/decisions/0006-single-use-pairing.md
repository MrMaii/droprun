# ADR 0006：限时单次配对码

状态：Accepted  
日期：2026-09-07

## 背景

旧 Relay 只比较长期 PAIR_HASH，同一码能无限创建设备；旧安装页展示静态码。配对是远程执行的入口，必须可过期、防重复兑换。

## 决定

- 只有 Connector Bearer 凭证可签发、查询状态或撤销邀请；手机不能签发。
- 当前单 Connector 部署只保留一个邀请槽。签发新码立即覆盖旧邀请，不影响已配对设备。
- 服务端用密码学随机数生成 80-bit 码，显示为四组五位十六进制字符；归一化大小写、空格和连字符。
- 有效期固定 10 分钟，以 Worker 时间为准，客户端不能延长。D1 只存 SHA-256、创建/过期/消费时间和兑换设备 ID，不存明文码。
- 消费邀请与插入新设备在一个 D1 batch 中完成，条件更新保证并发只有一个设备成功，插入失败整体回滚。
- 过期、已使用、被替换、撤销和旧静态码均返回相同 403；无旧码兼容降级。撤销已配对设备不复活其邀请。
- 现有设备 token、项目授权、任务和报告保持。配对码不直接授予项目执行权，新手机仍逐项确认。
- 本机运行 `node scripts/pair-device.mjs new` 生成码并刷新私人安装页，不打印明文。status 只读，revoke 只撤销未兑换邀请。PowerShell 入口为根目录 pair-device.ps1。
- APK 发布只刷新安装说明，不自动签发或轮换邀请。Android 0.1.4 的现有表单即可兑换，不需新 APK。

## 后果与限制

邀请在响应丢失后不能重复兑换取回 token；手机可在电脑重新生成码。可能留下已创建但手机未收到的设备记录，需要后续设备管理清理；不声称完整配对幂等恢复。

安装页和 .local/pairing.json 含短期明文，仅存本机且被 Git 忽略。页面到期隐藏不代替服务端校验；消费后页面可能仍显示已不可用的码。电脑与 Worker 时钟可能有偏差，以服务端结果为准。尚无独立速率限制或电脑端二次签名；80-bit 随机码降低在线猜测可行性，不替代完整滥用防护。

PAIR_HASH 旧绑定和 config.pairingCode 字段未删除，但新 Worker 不读取它们，不能再用于配对。不要回滚到重新接受旧静态码的 Worker。

## 验证

tests/pairing.test.mjs：8 个并发兑换仅一个成功、10 分钟 TTL、存储哈希、过期/替换/撤销/旧码拒绝、原手机保留、设备插入失败回滚。

真实部署与 Android 证据见 验收账本（历史私人验收记录，未随公开版分发）。线上过期分支使用专门测试邀请的哈希定向缩短有效期，不改现有设备或用户材料；不是声称真等了 10 分钟。

## 替代方案

未采用长期共享口令，因为没有单次性和暴露窗口限制；未采用六位短码，因为尚无配套在线速率限制；未扩展多 Connector/多租户管理，避免超出当前私人 MVP。

官方依据：[D1 batch](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)，2026-09-07 核对事务和失败回滚语义，并以 Miniflare 及线上竞争请求验证。
