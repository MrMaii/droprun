# ADR 0014：手机端 UI/UX 重构——纯黑仪表盘与分步分享浮层

日期：2026-09-13（Toronto）  
状态：已采纳；随 Android 0.4.0 实施。发布与验证状态见 0.4.0 发布记录（历史私人发布记录，未随公开版分发）。

## 背景

0.3.x 的手机端沿用 0.1.7 的渐层玻璃风格：首页是两个统计卡片加任务卡片，分享入口会打开完整的 App 页面（材料输入框、项目列表、留言、模型/强度并排在一页），配对只有扫码和一个"手动输入"按钮，扫码失败没有引导。用户在 2026-09-13 要求完全重构 UI 与 UX：只保留品牌调性与资产（青柠色、便签 droprun 字标、图标），后台（Relay、Connector 执行链路）不变；允许新增功能和删除既有功能。用户给出的设计方案原文见 [PRD 5.1–5.2](../product/PRD.md#51-首次连接)。

## 决定

1. **单一纯黑背景。** 手机端所有页面使用 `#000000` 底色、细线分隔的深灰表面；青柠色 `#B8EF73` 只用于主要操作、选中态和进行中状态。0.1.7 的渐层背景、玻璃卡片和 `BrandUi.java` 被 `Ui.java` 取代，后者是唯一的样式与动效入口（纯 Java，无 AndroidX，无 XML 布局）。品牌字标 `brand_logo.png`、启动图标、通知图标不变。
2. **首页只有一个紧凑列表。** 顶部品牌标记加右上角设置按钮；正文是 `ListView`，每条任务 1–2 行：第一行是任务的简短名称，第二行是项目和处理时间（已结束显示"用时 X"，进行中显示"已进行 X"，需要用户处理显示"等你处理"），行尾一个带文字说明的状态点。统计卡片、通知提示卡片等从首页移除，只保留一行按优先级选出的状态提示。点击进入独立的 `TaskActivity` 查看完整反馈报告（留言、受阻原因、计划审批、命令审批、预览、截图、报告、追问、停止/删除全部保留在详情页）。
3. **任务名称由模型生成。** 开始本轮时，工作区已经存在 Connector 标题指令和 `report.mjs` 标题解析代码；本轮不修改或重载后端。手机优先展示既有 `title`。旧任务、模型尚未返回或没有标题行时继续使用留言或来源暂名；不额外调用模型，也不声称会话刚创建就一定已有 GPT 名称。
4. **分享是独立的分步浮层，不打开主 App。** `ShareActivity` 使用半透明主题覆盖在来源 App 上，底部弹出三步面板，顶部小点表示当前步骤：
   - 第一步选择项目。未授权项目在毛玻璃对话框（Android 12+ 使用真实模糊，其余版本使用遮罩）里说明授权含义，绿色按钮授权后播放打勾动画再进入下一步。授权仍走既有 `POST /projects/:id/permission`。
   - 第二步留言（可留空）；仪表盘图标展开后切换模型和推理强度，默认值来自设置，本次更改不覆盖默认值。
   - 第三步无需操作：任务按原格式写入本机 outbox 并启动既有的限时接收服务，纸飞机飞向 Codex；文案只确认“已保存，自动发送”，并按预设模式说明材料读取后的计划或执行流程。约两秒后关闭，回到原来的 App。此步骤不请求通知权限，不用动画冒充后端接收或视频读取完成。独立 task affinity 避免返回主 App。
5. **扫码失败主动提示改用配对码。** 扫码页统计非 DropRun 二维码、20 秒无识别和相机错误；触发时弹出"改用配对码"提示。配对页累计两次失败后显示改用配对码的引导卡。配对码本身、一次性兑换和 `/pair` 接口不变。
6. **设置集中在一个页面。** 电脑连接、执行模式、默认模型与推理强度、各项目授权、关于。项目授权开关和执行模式风险确认沿用既有语义。

## 理由

用户明确指出旧首页信息密度低、分享流程"像打开一个 App"，并且希望从视频 App 分享时不离开原界面。纯黑底色和一行式列表让同屏容纳更多历史；浮层加自动关闭把分享压缩成"选项目、可选留言、看它飞走"。模型生成的标题解决了列表里全是留言开头或视频标题的问题，而不需要改 Relay。

## 后果

- Android 0.4.0 是覆盖安装升级，配对、缓存任务、设置保留；旧任务的详情、审批与预览功能完整保留在详情页，只是不再出现在首页卡片上。
- 本轮没有发布或重载 Connector；其运行中版本是否具备工作区标题代码不作为已验证事实。任何 Relay 字段、状态机、权限门禁都没有改变。
- 设置仅覆盖现有电脑连接与项目授权。多账户 OAuth 尚无后端契约，不用虚假入口代替。
- 毛玻璃效果依赖 `RenderEffect`（API 31+）；API 26–30 只有遮罩，不影响功能。
- 移除了首页统计卡片、可编辑的材料输入框（分享内容改为只读展示）与首页上的通知/离线提示卡片；这些属于用户授权删除的既有功能。

## 验证方式

Gradle `assembleRelease` 与 lint、三个纯 Java 单元测试、Node 测试全套；API 35 模拟器逐屏截图（首页、详情、设置、配对、扫码超时提示、分享三步与授权对话框）。实际结果只记录在 0.4.0 发布记录（历史私人发布记录，未随公开版分发）。

## 替代方案

- 保留旧首页并只换配色：不满足"完全重构"和 1–2 行列表的要求。
- 用 Relay 侧模型生成标题：需要新增 Relay 接口和模型调用，违反"后端不变"。
- 用 Compose/AndroidX 重写：引入大依赖并改变构建链，与现有纯 Java、无 AndroidX 的约束冲突。
