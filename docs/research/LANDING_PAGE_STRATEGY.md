# DropRun 桌面端 Landing 页策划

核查日期：2026-09-23（Toronto）  
状态：本轮页面方案，非新的产品功能决定。实现见 `landing/`。

## 参考观察

以下是对官网首页结构的定性观察，不代表转化率研究。

| 官网 | 页面表达 | 对 DropRun 的启发 |
| --- | --- | --- |
| [Linear](https://linear.app/) | 首屏一句定位，紧接可见产品界面，再按真实工作环节展开。 | 首屏同时呈现价值和双端工作画面，避免只讲抽象 AI 能力。 |
| [Notion](https://www.notion.com/) | 首屏定位与简短解释并列，马上给出产品画面和行动入口。 | 用一句可复述的话解释产品；首屏按钮直达工作方式。 |
| [Slack](https://slack.com/) | 先说明人和 agent 一起工作的结果，再以具体用途建立理解和信任。 | 把 agent 放进用户已有工作，而非把模型本身作为主角。 |
| [Raycast](https://www.raycast.com/) | 强识别度的主张、精细的产品视觉、后续场景和能力分区。 | 保留鲜明品牌语言与高质量界面示意，不做通用 SaaS 模板。 |

从这些页面归纳出的共同顺序是：一句价值主张、可见产品、具体使用过程、差异和可信依据、再次行动。DropRun 的特殊之处是跨手机与本地项目，因此首屏必须同时让人看懂两端。

## 1. 页面结构

单页叙事。桌面端优先，窄屏可读。导航只指向页面内已有内容；当前没有公开注册或购买路径，不放空按钮。

1. **首屏：价值 + 双端画面。** 主张“灵感，别停在收藏夹”；补充“手机分享、电脑上的 agent 工作、结果回手机”。电脑窗口和手机报告并置，标为示意界面。
2. **问题：收藏与执行之间的断层。** 把用户今天要做的复制、找项目、重述、追进展讲清楚。
3. **流程：分享 / 交办 / 交付。** 每步只有一个动作、一张小示意和一句结果；表达已有项目和原目录会话。
4. **产品细节：为什么是 DropRun。** 项目上下文、可选留言与自主判断、可核验交付。配报告示意，展示读取范围、应用位置和结果。
5. **原则：诚实与边界。** 实际读取了什么、哪些动作需单独授权、电脑离线时排队。
6. **当前阶段。** Android 私人测试，来源可读性和完整交付仍需继续验证。
7. **收束行动。** 再次引导浏览工作方式；等公开获取渠道确定后，才改成真实下载或申请入口。

## 2. 产品调性

- **定位：** 给已有项目的灵感交办入口；核心是从参考走到实际工作。
- **气质：** 安静、精确、有行动力。对 agent 能力不做夸张承诺。
- **视觉：** 延续现有品牌的深色基底、青柠强调与便签字标；用大标题、清晰网格、细线和真实感界面层次制造高级感。浅色问题段形成节奏变化。电脑和手机的比例关系是首屏核心视觉。
- **文案：** 先说用户得到的进展，再讲机制。主文案中文；少量英文用于编号和界面纹理。
- **证据：** 所有虚构任务画面标记“示意”；不放虚构客户、成功率、平台支持范围或已发布下载入口。

## 3. 每区信息与验收

| 区块 | 要回答的问题 | 页面要素 | 验收 |
| --- | --- | --- | --- |
| 首屏 | 这是什么、对我有什么用？ | 主张、副标题、行动按钮、电脑与手机示意 | 5 秒内可复述核心流程；示意标识可见 |
| 问题 | 现在为什么麻烦？ | 收藏夹反差、旧流程短链 | 不把 DropRun 说成知识库或稍后读 |
| 流程 | 我需要做哪几步？ | 分享、进入项目、结果回手机 3 卡 | 每卡动作和结果明确；不暗示离线电脑即刻执行 |
| 产品细节 | 为什么它能用于真实项目？ | 原目录、留言、自主判断、报告示意 | 报告讲材料范围、应用位置、真实工作 |
| 原则 | 我能信它吗？ | 读取范围、权限、离线行为 | 不把链接写成看完视频；高风险动作另行授权 |
| 当前阶段 | 现在能否公开使用？ | 私人测试说明 | 不提供无效下载或注册入口 |
| 收束 | 看完下一步？ | 回到流程的真实链接 | 所有按钮都有有效目标 |
