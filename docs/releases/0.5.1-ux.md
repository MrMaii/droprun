# 0.5.1 Android UX candidate — local validation

Updated: 2026-09-29. Status: **unreleased; not approved for a stable marketing launch**.
The public website and `v0.5.0-rc.1` downloads still use the previous candidate.
The user explicitly selected local UI validation only; real submissions remain
an acceptance gate. No new posters or campaign assets were generated ahead of it.

## Changes

- Quieter project cards with compact status/time, grouped settings and a result
  excerpt before the expandable full report.
- Ripple/press feedback on custom controls, internal navigation transitions and
  local disclosure animation. System animation-off remains supported.
- Computer/project names and setting values can wrap at large text sizes.
- Saved outbox items expose material, attachment count, failure and retry actions.
  A retry preserves task identity. Follow-up draft/identity restore with Activity
  state; local-save feedback does not claim server receipt.
- Permission grants require confirmation. Disconnect is grouped at the bottom
  of settings. Share success feedback returns to the source sooner.
- Closing a share with an unsent note now requires explicit discard confirmation.
  Keeping the editor preserves the text; neither option creates a task.
- Confirmation surfaces share the app's rounded corners, sentence-case buttons
  and 48dp minimum button height, in both appearance modes.

## Local transport regression, 2026-09-29

A minimal Worker that immediately returns 403 without reading the request body
reproduced `ECONNRESET` on Windows after 38 completed requests. Supplying the
known string body's UTF-8 Content-Length completed 1,000 requests to the same
minimal Worker. The test-only Miniflare adapter now supplies that header when
absent; existing explicit headers and production authentication are unchanged.
There are no automatic mutation retries and no weakened assertions.

`npm test` passes **191/191**, including a 200-request early-rejection regression.
The transport, approval/deletion and preview suites passed a second run, **28/28**.
Evidence: `.local/node-framed-sep29.log`, `.local/node-framed-repeat-sep29.log`,
`tests/miniflare-transport.test.mjs`. The previous 189/190 runs are historical
failures; this diagnosis replaces the earlier assumption that concurrency alone
caused them. It does not prove that all possible transport failures are eliminated.

## Local recovery regression, 2026-09-29

Six instrumented cases pass on the dedicated API 35 emulator, using native Views,
real local files and Android Keystore. The transport is synthetic and the fixture
Relay is `preview.example.invalid`; these tests do not submit to a real server.

- Follow-up text, task identity and expanded sections survive Activity recreation;
  cancelling keeps the draft and an empty follow-up is rejected.
- Interrupted uploads retain completed assets and upload only the missing file
  on retry; accepted tasks remove their local copies.
- A lost acknowledgement preserves the same task ID for retry.
- Changing the selected instance cannot reuse another instance's token or outbox.
- Closing an unsent share note requires an explicit discard decision.
- A foreign outbox record retains its original instance ID, is never submitted,
  and does not prevent a valid local record from being sent by the fake transport.

The last case reproduced an actual bug before the fix: saving an error retagged
the foreign record with the current instance ID. The failure path now only saves
records that already belong to the selected instance. Evidence:
`.local/android-foreign-before.log` (red), `.local/android-recovery-six-sep29.log`
(`OK (6 tests)`), and `LocalRecoveryTest.java`. After the dialog style change,
all six passed again in `.local/android-dialog-six-sep29.log` (9.18 seconds).

An earlier long-running emulator developed a system ANR. The affected runs were
not counted as passes; the same AVD was cold-started without wiping data before
the successful run. No physical-device performance claim follows from this.

Marketing readiness requires closing or explicitly accepting these gates with
the appropriate release scope; UI screenshots alone cannot establish it.
