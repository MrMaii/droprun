## Known acceptance gaps

- No physical Android device available this session. Device background delivery,
  OEM behavior, TalkBack and the specified frame/latency targets remain unverified.
- Twenty real source-platform samples and five continuous genuine mobile-to-Codex
  tasks across three real projects are not replaced by fixtures or demo screens.
- Clean Windows installation and cloud-account onboarding require independent
  field validation even when a package can be built and locally diagnosed.
- Preview support is limited to compatible static exports; backend-dependent
  applications require the owner's optional managed live-preview infrastructure.
- Windows packages have no claimed trusted code-signing identity.

## Compatibility and recovery

The public Android application coexists with the old private package. Pair it with
a compatible Relay; do not uninstall the old app merely to bypass signing errors.
Fresh cloud instances use the new baseline. Old instances require explicit backup
and upgrade; public installation must not overwrite a historical private config.
Keep previous binaries and data until health and a handoff pass after updates.
Windows installation now checks the configured Relay and backs up the old app and
data before replacement. Portable backups and cloud backups/recovery remain owner
actions; no automatic cloud rollback is claimed. See the bilingual self-hosting
guides for the exact recovery steps.
