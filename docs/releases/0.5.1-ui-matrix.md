## Visual and interaction boundaries

- Native controls use the shared press/focus states; page/disclosure transitions
  respect system animation settings. Ordinary selection changes show the selected
  value. Additional confirmations are reserved for discarding work, destructive
  actions and granting execution/access.
- API 26 fallback uses opaque surfaces. API 35 and API 26 local font/keyboard
  evidence is in the release record. This does not establish TalkBack completeness.
- Settings scroll-boundary regression checks actual visible content bounds against
  system-bar insets; inspection exposed overlapping clock/content before the fix.
- Permission overlays scroll inside a fixed rounded surface, avoid navigation bars,
  block keyboard focus behind them, and use opaque surfaces on older Android.
- Failure messages must remain perceivable after polling. Effective command and
  preview expiry must update even when cached JSON is unchanged. Expired requests
  must explain the need to refresh, rather than point to a missing approval button.
- Reading status must describe attempted access, not promise that video, audio or
  frames have already been obtained. The final report owns actual material coverage.

## Release boundary

No row marked local-only substitutes for the real acceptance gates: physical
Android/performance, 20 genuine source samples, five complete tasks across three
projects, clean Windows/Cloudflare setup, update/uninstall, and public release
verification. Marketing readiness remains unproven until those gates are met or
the user explicitly accepts a different release scope.
